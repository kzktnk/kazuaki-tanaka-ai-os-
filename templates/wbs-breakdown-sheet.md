# WBS分解シート｜上位タスクの詳細化テンプレート

## 目的
上位タスクを「成果物・完了状態」から逆算し、第三者が追加説明なしで着手できる粒度まで分解する。考え方の解説は `playbooks/wbs-design.md` を参照。

## STEP 1｜上位タスクの完成形を定義する

| 項目 | 記入欄 |
|---|---|
| 上位タスク | |
| 目的（なぜやるか） | |
| 完了状態（何がどうなれば終了か） | |
| 成果物（何を残すか） | |

## STEP 2｜分解の材料を洗い出す

| 観点 | 問い | 記入内容 |
|---|---|---|
| Input | 開始するために、何を集める／受け取る必要があるか？ | |
| Decide | 成果物を完成させるために、何を決める必要があるか？ | |
| Stakeholder | 誰から情報をもらう／誰と合意する必要があるか？ | |
| Produce | 実際に何を作成・整理・分析する必要があるか？ | |
| Review | 誰に、何を確認してもらう必要があるか？ | |
| Approve / Close | 何をもって完了とするか？ | |

## STEP 3｜実行タスクへ落とし込む（準備 → 実施 → 確認・完了）

| No. | フェーズ | 詳細タスク | タスク説明 | Input | Output／完了状態 | 開始 | 終了 | 期間(日) | 依存タスク | レビュー／承認者 | ステータス |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 1 | | | | | | | | | | | 未着手 |
| 2 | | | | | | | | | | | 未着手 |
| 3 | | | | | | | | | | | 未着手 |

（行は必要なだけ追加する。フェーズには「準備／実施／確認・完了」のいずれかを記入）

## STEP 4｜詳細化セルフチェック
- [ ] 各タスクは「何をするか」が動詞で明確になっているか
- [ ] 各タスクのOutput／完了状態を説明できるか
- [ ] 前後関係・依存関係が明確になっているか
- [ ] レビュー・承認の作業が抜けていないか
- [ ] 担当者が渡されたとき、追加説明なしで着手できる粒度か
- [ ] 1つのタスクに複数の異なる作業を詰め込みすぎていないか
- [ ] 上位タスクの完了状態と、詳細タスク群のOutputがつながっているか
- [ ] 『検討する』『対応する』だけの曖昧なタスク名になっていないか

## 分解チェックリスト（WBS完成後の自己採点用）
使い方：WBS作成後に自己採点する。NGが集中する観点が、その人の「思考停止ポイント」。

| No. | 観点 | 確認質問 | 自己評価 | 他者レビュー | 改善メモ |
|---|---|---|---|---|---|
| 1 | 完成形 | この上位タスクが終わった状態を具体的に説明できるか | | | |
| 2 | 成果物 | 最終的に何を残すのか明確か | | | |
| 3 | Input | 着手に必要な資料・情報・前提条件を洗い出したか | | | |
| 4 | 意思決定 | 何を決めなければ成果物が完成しないか分解したか | | | |
| 5 | 関係者 | 情報提供者・協議者・承認者を特定したか | | | |
| 6 | 工程 | 準備→実施→確認・完了の時間軸で作業を再生したか | | | |
| 7 | 粒度 | 第三者が追加説明なしで着手できる粒度か | | | |
| 8 | 依存関係 | 前提タスク・後続タスクを確認したか | | | |
| 9 | Review | レビュー・指摘反映の作業を明示したか | | | |
| 10 | Approve | 何をもってCloseするか明示したか | | | |
| 11 | 表現 | タスク名が具体的な動詞で書かれているか | | | |
| 12 | 整合性 | 詳細タスクを全部終えれば上位タスクが本当に完了するか | | | |

## 使用例｜「検証計画策定」を詳細化する

**STEP 1**

| 項目 | 記入内容 |
|---|---|
| 上位タスク | 検証計画策定 |
| 目的 | 検証の対象・方法・評価基準を明確化し、関係者が同じ方針で検証を実施できるようにする |
| 完了状態 | 検証計画書が関係者レビューを経て承認されている |
| 成果物 | 検証計画書 |

**STEP 2**

| 観点 | 記入内容 |
|---|---|
| Input | RFP、提案書、要件、既存検証資料 |
| Decide | 検証対象、評価観点、評価指標、測定方法、合格基準、体制、スケジュール |
| Stakeholder | プロジェクト責任者、業務担当、アプリ担当、ベンダー |
| Review / Approve | 内部レビュー → 顧客レビュー → 指摘反映 → 承認 |

**STEP 3**

| No. | フェーズ | 詳細タスク | Input | Output／完了状態 | 依存 | レビュー／承認者 |
|---|---|---|---|---|---|---|
| 1 | 準備 | 関連資料を収集する | 既存資料 | 必要資料一式 | ― | |
| 2 | 準備 | 検証対象を整理する | 必要資料一式 | 検証対象一覧 | 1 | |
| 3 | 実施 | 評価観点を整理する | 検証対象一覧 | 評価観点一覧 | 2 | |
| 4 | 実施 | 評価指標を設定する | 評価観点一覧 | 評価指標一覧 | 3 | |
| 5 | 実施 | 合格基準を設定する | 評価指標一覧 | 合格基準一覧 | 4 | |
| 6 | 実施 | 検証方法を設計する | 評価指標・合格基準 | 検証方法 | 5 | |
| 7 | 実施 | 計画書ドラフトを作成する | 各検討結果 | 検証計画書ドラフト | 6 | |
| 8 | 確認・完了 | 内部レビューを実施する | 計画書ドラフト | 内部レビュー済み計画書 | 7 | 内部責任者 |
| 9 | 確認・完了 | 顧客レビューを実施する | 内部レビュー済み計画書 | 顧客指摘一覧 | 8 | 顧客責任者 |
| 10 | 確認・完了 | 指摘を反映し計画を確定する | 顧客指摘一覧 | 承認済み検証計画書 | 9 | 顧客責任者 |
