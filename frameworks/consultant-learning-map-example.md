# Consultant Learning Map（プロトタイプ）

**対象：** 〇〇さん
**Skill：** 構造化する（Capability I｜Thinking / Problem Solving）
**現在地：** L1（型を知る） **［Assessment Status：Confirmed／判定者：指導者〇〇、判定日：20XX-XX-XX］**
**現在のアサイン：** 複数PJ横断案件（Cross-Project Program Managementのご担当予定）

---

## 今できていること（L1・確定済み）

Pattern選定の理由と箱の中身を自分の言葉で説明でき、指導下で構造化を1回実施できる状態です。

## 次に目指すところ（L2）

**指導者なしで、自分の力で構造化を最後までやり切れる状態**です。目安として、標準的な論点2件以上で、Pattern選定・箱の中身・AIレビュー観点の3点を満たした状態まで自力で完成させ、なぜそのPatternを選んだのかを自分の言葉で説明できることを想定しています。

## やってみてほしいこと

1. 実際に担当する案件から、構造化が必要な論点を1つ選んでみましょう
2. `frameworks/thinking-patterns/`から合う型を自分で選び、AIを使う場合は「箱（構造）を渡してから埋めさせる」順番を守ってみましょう
3. AIが埋めた中身は、そのまま使わず自分でレビューしてみましょう
4. 条件の異なるもう1件でも、同じように進めてみましょう

## できたら見せてほしいもの

構造化した内容と、その型を選んだ理由を指導者に説明してください。2件目まで終わったら、L2への到達を判定します。

## 次のSkillについて

構造化がL1以上になると、`playbooks/wbs-design.md`（Work Planning／WBS）に進みやすくなります。ただ、今のアサイン（複数PJ横断案件）を踏まえると、`playbooks/cross-project-program-management.md` Ch3のDependency Managementも並行して見ておくと役に立つと思います。どちらを先にするかは、指導者と相談して決めてください。

---

**この用紙について**：この1枚は`frameworks/consultant-capability-skill-model.md`（Capability Model本体）から、対象者のCurrent LevelとRole／Assignmentに応じて機械的に組み立てています。Capability Model側の内容が更新されたら、この用紙も更新の対象になります。

**Assessment Statusについて**：現在地のLevelには必ずConfirmed（判定者・判定日つきで確定済み）かProvisional（自己申告・未判定）のいずれかを明記します。Provisionalのまま次のLearning／OJTへ進めることは可能ですが、次のLevelの判定（Evidence確認）はConfirmedな現在地を前提に行います。
