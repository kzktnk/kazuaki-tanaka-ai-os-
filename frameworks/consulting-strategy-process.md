## Purpose

Define the **end-to-end consulting strategy engagement lifecycle** — from problem definition through analysis, solution identification, and client buy-in.

Use this framework when:

- Scoping a strategy, market, or transformation engagement
- Structuring ambiguous executive questions into analyzable work
- Connecting problem framing → analysis plan → findings → recommendations
- Coaching teams on disciplined strategy consulting (not ad-hoc research)

This complements:

- `core/reasoning.md` — default reasoning sequence
- `frameworks/strategic-capability-network.md` — capability mapping after strategy direction is clear
- `frameworks/program-phases-investigation-to-requirements.md` — phased investigation programs
- `frameworks/transformation-pmo.md` — multi-project execution after strategy is set

## Engagement Lifecycle

```
┌─────────────────────────────────────────────────────────────────┐
│  SCOPE PROBLEM & APPROACH (early — do not skip)                 │
│  Define Problem → Structure Problem → Plan Approach             │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  SOLVE THE PROBLEM                                              │
│  Collect & Synthesize Data → Assess Findings → Identify Solutions│
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  COMMUNICATE RECOMMENDATIONS                                    │
│  Evaluate Stakeholders → Develop Logical Communications → Deliver│
└─────────────────────────────────────────────────────────────────┘
```

**Parallel track (all phases):** Develop team and manage project administration.

**Anti-pattern:** Random, unrelated issues — workstreams that do not trace to the key question or logic tree.

**Target outcome:** Comprehensive, defensible recommendations with client buy-in.

## Phase 1 — Scope Problem & Approach

Apply **early**. Skipping this phase is the highest-risk efficiency trap (wrong problem, rework, misaligned client expectations).

| Step | Key question | Primary tool | End product |
|------|--------------|--------------|-------------|
| **Define the problem** | What is the key question to be answered? | **4Cs & 1Q** | Consensus on a well-defined, customized problem statement |
| **Structure the problem** | What issues are associated with the key question? | **Logic tree** (MECE) | Logically decomposed problem components |
| **Plan the approach** | What analyses and end products address the issues? | **Analysis plan** (+ storyboard, work plan) | Consensus on scope, analysis, timing, deliverables |

### 4Cs & 1Q (problem definition)

| Element | Focus |
|---------|--------|
| **Context** | Key issues confronting the client; industry and company situation (e.g. business system, 3-C, 5 Forces, 7S as lenses — not as substitutes for judgment) |
| **Client** | Decision maker, influencers, sensitivities, biases, prior consultant experience, impact on client role |
| **Criteria** | How the client will decide whether to act — financial, congruence with identity/strategy, risk, timing |
| **Constraints** | Scope boundaries — business lines, org units, resources, information availability |
| **Question** | The specific question this study must answer |

**Principles:**

- Iterative and participative — no single pass sign-off
- Everyone has a partial view; synthesis beats any one person's framing
- Criteria and constraints shape what "good recommendations" mean before analysis starts

### Logic trees (problem structuring)

Decompose the key question into a **MECE** (Mutually Exclusive, Collectively Exhaustive) set of issues.

**Problem iceberg:** Visible phenomena sit above the water; structuring exposes underlying/root causes.

| Tree type | Starts from | Best when | Endpoints |
|-----------|-------------|-----------|-----------|
| **Deductive** | Desired result or broad question | Early exploration; generating alternatives | Actions, assertions, criteria, questions |
| **Hypothesis** | Proposed solution or decision | Evaluating one well-defined alternative | Rationale and analyses to prove/disprove |
| **Issue map (Yes/No)** | Broad strategic question | Choosing among multiple alternatives | Yes/no issues with implied actions |

**Selection heuristics:**

| Familiarity with domain | Issue specificity | Typical starting tree |
|-------------------------|-------------------|------------------------|
| Low | Broad | Deductive → refine to hypothesis or issue map |
| Moderate | Mixed | Deductive or issue map |
| High | Specific alternative | Hypothesis tree |

Also consider: stakeholder bias, required confidence, time and resources.

**MECE discipline:** No gaps, no overlaps. Use framework knowledge (deduction, induction, consulting toolkit) to test splits. Pyramid Principle applies — tree structure often becomes document structure.

### Analysis plan chain

The analysis plan links the logic tree to execution:

```
Issue → Hypothesis → Analysis → Information source → End product
```

Leads to:

1. **Storyboard** — slide storylines as standalone chapters of the final story
2. **Work plan** — tasks, timing, responsibility (minimum three elements)
3. **Contract / formal agreement** — scope, end products, staffing, timing, contingencies

**Benefits of approach consensus:** Budget realism, scope-creep control, early identification of high-value vs low-value analysis, stakeholder buy-in on cost/benefit of additional research.

## Phase 2 — Solve the Problem

Most team time sits here: gathering data, synthesizing implications, generating **so-whats** that drive recommendations.

### Strategy analysis structure

```
Situation Assessment                    Strategy Formulation & Evaluation
─────────────────────                   ─────────────────────────────────
Internal: Company analysis              Create preliminary strategic options
External: Customer + Competitive        Evaluate options (suitability,
         analysis (3-Cs lens)            feasibility, acceptability)
                                        Select optimal strategy
```

**Key question split:**

- *"What is the situation?"* — assessment
- *"What are the best options?"* — formulation and evaluation

### Strategy levels

| Level | Focus |
|-------|--------|
| **Corporate** | Which industries/businesses to compete in |
| **Business unit / divisional** | Products, services, markets |
| **Functional** | Competitive advantage from specific functions |

### Typical strategy problem types

| Type | Focus | Complexity |
|------|-------|------------|
| Market assessment | Structure and forces in current/future marketplace | Narrow |
| Capabilities assessment | Sufficiency of capabilities for strategic goals | Narrow |
| Opportunity assessment | Whether to pursue a new opportunity | Narrow |
| Corporate planning / strategy development | Business plan, planning process, strategic options | Broad |
| Marketing strategy | Brand, identity, program effectiveness | Broad |
| New product / service development | Market entry with new offering | Broad |

**No silver bullets:** Tools do not add value; consultants add value by pushing tools to insights and so-whats.

### Primary analysis tools (by phase)

| Phase | Internal | External | Formulation / evaluation |
|-------|----------|----------|--------------------------|
| Situation | 7S, value chain, core competency, SWOT, profitability/cost, SVA/EVA | 5 Forces, value chain, 2×2, benchmarking, positioning map, segmentation | Scenario envisioning, gap analysis, fit vs attractiveness |
| Evaluation | — | — | NPV/IRR/SVA/EVA, sensitivity, implementation requirements |

See `standards/strategy-engagement-guide.md` for operational detail on data gathering, scenarios, and solution evaluation.

### Data gathering (summary)

After hypothesis and analysis plan:

1. Define data requirements (analysis-driven + stakeholder/context needs)
2. Develop data gathering plan (sources, methods, sequence, responsibilities)
3. Gather data (interviews, workshops, surveys, research, observation)

**Interview uses:** Hypothesis generation, hard data, perspective/validation (blind spots, feasibility, politics, credibility).

**Typical interview order:** Client senior management → technical/sales → industry experts → customers → distributors → substitutes → competitors → suppliers.

## Phase 3 — Scenario Envisioning

Use when industry or market change is **moderate to high** (static → incremental → discontinuous change).

**Role in strategy flow:** Bridges situation assessment and option creation/evaluation — *What is happening? What responses? Which options maximize advantage?*

### Ten-step process (condensed)

| Step | Activity |
|------|----------|
| 1–2 | Define future industry/market context; identify paramount driving forces |
| 3–4 | Set boundary parameters; develop hypotheses on force interactions |
| 5–6 | Create scenario set; test credibility via enabling events |
| 7–8 | Plot evolutionary paths; simulate outcomes (customers, business systems, competition) |
| 9–10 | Assess client capabilities per scenario; develop and select strategy portfolio |

**Application modes:**

- **Standalone lead-in** — exploratory workshop before full strategy project
- **Embedded** — within Phase I–III strategy program alongside market/competitive/internal analysis

**Driving-force prioritization:** Brainstorm forces → plot Impact vs Uncertainty → select key forces for scenario building.

## Phase 4 — Solutions Identification

Final step of "Solve the Problem" — evaluate and select options; do not jump here without assessment and option development.

### Decision criteria

Minimum requirements a strategy must meet (needs). Anything beyond minimum = benefits.

Develop criteria across:

- Scenario implications and environmental opportunities/threats
- Sustainable competitive advantage (strengths/weaknesses vs competitors)
- Vision and objectives (long-term ROI, compatibility)
- Feasibility (resources, organization, implementability)
- Portfolio and synergy (balance, flexibility, cross-business fit)

### Diamond-E lens (strategic fit)

| Element | Question |
|---------|----------|
| **External environment (EE)** | What does the environment require? |
| **Resources (R)** | What can the organization do? |
| **Organization (ORG)** | Can structure and processes support it? |
| **Management preference (MP)** | What does leadership want? |
| **Strategy (S)** | The chosen option |

**Needs / Wants / Cans:** Ideal strategy fits all three; gaps indicate where to architect strategy, procure resources, or reset expectations.

### Option evaluation

| Dimension | Examples |
|-----------|----------|
| **Suitability** | Return vs baseline, NPV/IRR/SVA/EVA, sensitivity, implementation requirements |
| **Feasibility** | Ease, probability of success, capabilities, risk |
| **Acceptability** | Cultural fit, stakeholder satisfaction |

Score options against explicit criteria; the option meeting most criteria (with trade-offs documented) becomes the recommendation.

**Issue prioritization (implementation themes):** Separate **importance** (why must we act?) from **feasibility** (cost, time, resources/skills). Map themes on a 2×2 to sequence work.

## Phase 5 — Communicate Recommendations

| Step | Focus |
|------|--------|
| Evaluate stakeholders | Who decides, who influences, resistance patterns |
| Develop logical communications | Pyramid structure; storylines from storyboard |
| Deliver | Presentation and buy-in; link back to criteria agreed in problem definition |

**Resistance pyramid:** Awareness → understanding → acceptance → ownership (aligns with change management in PMO materials).

## Common Failure Modes

| Failure | Symptom | Mitigation |
|---------|---------|------------|
| Skip problem definition | Client focused on symptom not root question | 4Cs & 1Q workshop; iterate with stakeholders |
| Unstructured analysis | Random issues, no MECE | Logic tree before work plan |
| Tool-first consulting | Framework slides without so-whats | Every analysis ends in "so what for the key question" |
| Analysis paralysis | Scope creep, no end product | Analysis plan with end products and storyboard early |
| Criteria after the fact | Recommendations client won't adopt | Capture Criteria in 4Cs before deep analysis |
| Scenario as prediction | Single future assumed | Multiple scenarios; test strategies across them |
