# Pattern: Change Agent vs Communication Plan

**Status:** Active  
**Origin:** Anonymized coaching on customer-facing monthly status and change-management artefacts (Program Line AE, 2026-08-28). Client facts, names, and schedule numbers are **not** stored here.

## Pattern statement

> **チェンジエージェント（旗振り役）を見つけることが、コミュニケーション計画の目的ではない。計画が答えるのは、関係者の中にコミットメントが低い人が現れたとき、どう上げるかである。**

BPR／定着の現場では、既存の構築メンバーがすでに旗を振っていることが多い。残りは「理解して自分たちでできるようになる」側——末端の定着対象——になりやすい。その構図なら、新規に「一緒に旗を振りましょう」役を探す効果は薄い。エージェントが無くてもチェンジが進むなら、作らなくてよい。

コミュニケーション計画は別物である。いま見えていない関係者を含め、**両度（コミットメント）が低い人が出たときにどう上げるか**を、計画の中で決める。Stakeholder Activation の Champion 化（`playbooks/stakeholder-activation-playbook.md` Chapter 7）は、その計画の戦術層であり、エージェント探索そのものではない。

## Signals

- 「チェンマネ＝キーマンを見つけて育てる」で成果物が止まっている  
- 既存の旗振り役がいるのに、新規エージェント探しが管理対象になっている  
- 反対派・低コミットメントが出たときの上げ方が、エージェント不在と同一視されている  
- 付録サンプルから先に埋め、変革推進計画の骨格が後回しになっている  

## Plan first, artefacts second

サンプルや知識エリアのマッチング表は、計画の骨格の**あと**で必要性が決まる。サンプルはサンプルのままにする（実データまで描くと事例になり、次工程で情報が取れるかの確認に使えない）。過去事例は今回の顧客に合わせてよい。カスタマイズは異常ではない。

## Tests

- コミュニケーション計画の一文が「誰をエージェントにするか」ではなく「低コミットメントが出たときの上げ方」になっているか  
- 既存の旗振り役で進むなら、新規エージェント探索を必須にしていないか  
- 変革推進計画の骨格（目的・範囲・ステークホルダー・コミュニケーション）が、付録より先にあるか
