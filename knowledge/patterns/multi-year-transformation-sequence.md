# Pattern — Multi-Year Transformation Sequence

**Version:** v0.1  
**Status:** Active  
**Type:** Knowledge pattern  
**Owner:** Kazuaki Tanaka  
**Pattern name:** Multi-Year Transformation Sequence  
**Applies to:** オーナー企業・事業会社の多年改革、基幹遅延、購買改革、人事・文化

---

## Pattern

> **多年の改革は、戦略 → 実行 PMO → マネジメントスタイル → 顧客体験 → 現場コスト → 人事 → 文化の定着 → システム → 購買、の順で負債が残る。後工程のシステムは、前工程の経営情報と権限が無いと判断不能になる。**

典型的な切れ方:

- 中長期戦略のあと、実行フェーズの PMO が無いと計画は棚に残る  
- スタイル・CX・コストは現場に入るが、人事・規程が古いと行動が戻る  
- 研修は文化の定着装置であり、制度変更の代替ではない  
- 基幹が遅延していることと、その状況で経営判断できる情報がないことは **別問題**。遅延復旧だけ請けても判断は回復しない  
- 購買が見積依頼と一次交渉のルーチンに閉じていると、基幹再構築は「今の購買を速くする」になる。品目カテゴリでの集中と、開発がサプライヤを決める構造を先に見る  

## Signals

- 戦略報告の翌年、実行支援が「会議体」だけ  
- システム PJ が大幅遅延、経営は進捗の数字以外を持たない  
- 基幹提案と購買改革が同じキックオフなのに、購買の権限は工場／カンパニーのまま  
- 人事規程とリーダー研修が別プロジェクトで、評価は従来  

## Underlying mechanism

システムは仕事と権限の写像である。戦略と人の型が決まっていないと、再構築は現行の局所最適を固定する。購買は製造原価のレバーだが、ルーチン作業のままではレバーにならない。

## Implications

多年プログラムを「案件の箱」の時系列として設計する。後から基幹だけ救う依頼が来たら、経営判断に必要な情報の欠落と購買の権限構造を同じ診断に載せる。

## Exceptions

- 法令対応だけの限定改修  
- すでに権限・情報・購買カテゴリが揃い、システム遅延だけが残っている  

## Do not

- 地域・業種が特定できる社名、原価構成比、支店研修の中身を登録する
