# Pattern: Buyer-Side Gap vs Vendor PMO

**Status:** Active  
**Origin:** Anonymized coaching on next-phase staffing and buyer-side accountability in a multi-vendor program (Program Line AE, 2026-08-28). Client facts, names, yen, contract dates, and headcount are **not** stored here.

## Pattern statement

> **開発側 PMO が「やっている」は、発注側のハザマ管理の代替にならない。最後に血を見るのは発注者である。ベンダー流の事務局では抜けが残り、その抜けはコンサル側に期待されやすい。**

開発サイトとしての PMO は、開発サイトのやり方で回る。発注者側で最後まで持たないといけない隙間（受け渡し、交点、方針と現場のあいだ）は、そちらでは拾われない。「当日 PMO がカバーしているから」とスコープ外に置くのは危険である。

いまの契約スコープはいまの契約である。無理に今フェーズへ広げなくてよい。ただしプログラムが進むと現場入りと交点管理は増える。現行期間のあとで隙間が見え始める、というのが次フェーズの会話になる。

## Continuation is not incremental value

次フェーズの体制を「今の延長」「月次で現地に出ているから安く聞ける」で正当化すると弱い。継続は当たり前と見られ、増分が見えない。規模を盛るのも不可。要るのは、**規模と確度の両方**が説明できる隙間の物語である。

顧客向け月次は、その物語の前段になる。基幹刷新は十年に一度の仕事であることが多く、顧客側に筋の記憶がない。普段からやっている側が、カットオーバーに向かうリスクと「今のままでは届かない」を月次に折り混ぜて理解を積む。見せ方は Program Line Z（Archetype J）。本パターンは **誰の隙間か／次に何を買うか** である。

現行契約の変更は難しいことが多い。次契約で体制を置く。過去の同型プログラムでストリームごとに複数人を付けていた、という記憶は、薄さの警告にはなるが、数字は案件に残さない。

## Signals

- 「ベンダー PMO が人数を持っている」だけで発注側の隙間を閉じたつもりになっている  
- 次フェーズ根拠が継続・月次同席・ロビーコストになっている  
- 月次が進捗％で、カットオーバー経路のリスクが語られていない  
- 今契約に仕事を足せば足りる、で次の体制議論を先送りしている  

## Tests

- ハザマ（交点・受け渡し・発注者最終責任）の持ち主が、開発側 PMO 以外に名前があるか  
- 次フェーズの一文が「続ける」ではなく「どこが足りなくなるか」になっているか  
- 月次で、顧客が十年に一度しかやらない仕事の火種を先に見せているか
