# Pattern: Experience Before Scope

**Status:** Active  
**Origin:** Generalized from utility retail portal / customer-experience working groups (Program Line K)

## Pattern statement

Customer-facing DX should not start from a feature list. Scope is the last step:

**Experience → capabilities → process change → data needed → implementation range (including what not to do in the transition).**

## Core distinction

### Feature-first

Screens, integrations, and algorithms are listed first. Business change and data readiness arrive as surprises. Expensive source data (interval usage, real-time simulation) gets committed before anyone decides it is worth the transition cost.

### Experience-first

Scenes of use are agreed. Functions exist only to serve those scenes. Process owners say what work changes. Data needs are derived. Implementation is cut against transition constraints.

## Signals

- Portal / CRM / contact-center programs arguing screens before journeys
- VIP / “important customer” labels appearing before KGI / CSF
- Multiple KPIs with no single process they improve
- Tariff or usage simulation scoped before CIS data timing is decided

## Core rule

> If the experience and the process do not change, the feature is not a requirement yet.
