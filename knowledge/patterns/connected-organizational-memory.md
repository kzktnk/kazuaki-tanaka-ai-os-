# Pattern: Connected Organizational Memory

**Status:** Active  
**Origin:** LinkedIn No.20 (author voice, lock A)

## Pattern statement

Capture without connection produces a **repository**, not organizational memory. Memory requires links across similar situations, earlier reasoning, and outcomes.

## Core distinction

### Accumulation / retrieval

Exception logs and search answer: *What do we have about this?*

Each record may make sense on its own. Months later, similar cases sit side by side with no relationship: why the decisions differed, whether they still apply, what happened afterward.

### Connected memory

Organizational memory also asks:

- Have we seen this before?
- What did we decide?
- Why?
- What happened next?

The missing piece is often not information. It is the **relationship between the pieces**.

## Failure modes (connection, not capture)

- The same exception at multiple sites, with none knowing the others exist
- Recurrence every few months, reasoning reconstructed from scratch each time
- Recurrence so frequent it is no longer exceptional — yet the standard never changes

## Connection habits

Do not start with a large knowledge-management program. A few habits may be enough:

1. When capturing an exception, check for similar cases.
2. When it is resolved, record what happened next — did the workaround hold, did the equipment operate safely, did it create another problem?
3. Occasionally ask: **should this still be an exception?**

## Standard-review signals

Frequency, consistent reasoning, and recurrence across sites are **clues**, not a formula. When they overlap — for example the same equipment stop, for the same reason, at three sites — review may need to cover not only how the exception is handled, but whether the **standard still fits current reality**.

Some exceptions should remain exceptions. Others may be telling us something about the standard.

## AI role

Connect related cases, surface patterns, and bring earlier reasoning forward when a familiar situation appears again.

Not: turn every exception into a new procedure.

The **timing** of that return—before the decision, without owning it—is `knowledge/patterns/memory-at-decision.md` (No.21).

Whether recurring exceptions should **change the standard**—with a human owning that change—is `knowledge/patterns/standard-as-learned-memory.md` (No.22).

## Core rule

> Accumulation gives us a repository. Connection may be what turns it into memory.

## Signals

Use this pattern when:

- Exception capture exists but entries are not reused
- Search returns similar cases with conflicting decisions and no outcome trail
- The same deviation repeats across sites or over months
- AI/RAG is treated as document retrieval rather than memory of prior reasoning
