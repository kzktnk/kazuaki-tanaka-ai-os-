# Pattern: Activation First for Site-Led Work

**Status:** Active  
**Origin:** Generalized from a change-management working session on a running multi-project program (2026-09). Client names, site names, org charts, named people, and recordings are **not** stored here.

## Pattern statement

> **本社だけで閉じる仕事と、現場が主体の仕事を仕分けるのが先である。現場主体なら、名簿やモデルサイト選定から入らない。検証テーマを先にピン止めし、サイトはそれに従う。組織・役割を先に置き、個人名は「個人レベルで管理すべき相手」だけにする。**

定着コミュニケーションと策定の場の切り分けは `knowledge/patterns/formulation-comms-vs-adoption-comms.md`。本パターンはその先：現場主体の仕事があるとき、**Activation（誰をどの状態へ動かすか）が入口**であり、ステークホルダー表を埋めることが入口ではない。

## Core distinction

| 先に決める | 後でよい |
|---|---|
| 本社だけで合意できるか / 現場リードが要るか | 個人名の一覧 |
| 現場リードなら、誰を巻き込む役割か（部門・職位） | モデルサイトの愛称 |
| 何を検証するか（テーマ）。サイトはテーマに従う | テーマが空のままサイトを先に決める |
| 現場チームを入れる前に、何を整備するか（権限・対象業務・データ・止められる範囲） | チーム派遣そのものをマイルストンにする |
| 本社が示す現場像か、現場が自ら目指す姿を書くのか | 両方を同じ「目指す姿」欄に混ぜる |

現場主体の施策で「クイックに AI 検証する」だけが決まっているなら、入口はもっと手前である。検証テーマの選定方法、現場が始められる条件、本社提案 vs 現場起案のどちらで姿を書くか、が先。

個人レベルの表は、影響力と受容が本線を左右する相手に限る。組織マップの空欄を氏名で埋める作業を、当日の主成果にしない。

## Signals

- チェンマネ検討会の主成果が、空の氏名欄を埋めることになっている  
- モデルサイトを先に決め、あとから検証テーマを探している  
- 「現場チームを入れる」が決まっていて、何を整備すれば入れるかが空欄  
- 本社だけで足りる施策と、現場リードの施策が、同じ巻き込み計画に載っている  
- 本社の示す現場像と、現場が自ら書く姿が、同じ To-Be として扱われている  

## Core rule

> Sort HQ-closable vs site-led first. Pin the verification theme before the site. Map roles before names. Activation is the entry, not the roster.
