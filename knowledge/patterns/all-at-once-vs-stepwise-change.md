# Pattern: All-at-Once vs Stepwise Change

**Status:** Active  
**Origin:** Legacy Change Strategy training (Program Line L)

## Pattern statement

Change strategy is a **configuration choice**: move the organization in one cut, or in sequenced steps. Neither is inherently mature. The wrong choice shows up as overload or as permanent dual running.

## Core distinction

### All-at-once

Use when processes, data, or regulation cannot run half-old and half-new. Cost is a spike of confusion unless communications, rehearsal, and support are sized for the cutover.

### One-step-at-a-time

Use when commitment and skill must be earned, or value can be released in slices. Cost is drift: temporary interfaces become the operating model.

## Design tests

- Can the employee’s calendar absorb the message load (no long silence, no stacked spikes)?  
- Does each step transfer **ownership**, or only install software?  
- Is “temporary” dual running time-boxed with a kill date?
