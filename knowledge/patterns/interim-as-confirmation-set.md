# Pattern: Interim as Confirmation Set

**Status:** Active  
**Origin:** Generalized from an interim-report pack on a running multi-project program (2026-09). Client names, plant names, filled issue rows, and recordings are **not** stored here. No transcript was provided; oral remarks were not harvested.

## Pattern statement

> **中間報告の仕事は、抽出過程の作業紙を見せることではない。共有前提を先に固定し、今期解くべき Critical / High に絞った確認セットで方向性を取り、スケジュールは現行 → 課題載せ → 更新案の順で止める。巻き込みと期限が両立しないなら、オプションを先に出す。**

課題の切り方（図は位相、表は課題）は `knowledge/patterns/topology-map-vs-issue-log.md`。本パターンは **その作業紙を、確認の場にどう載せるか** である。

## Core distinction

| 作業紙 | 確認セット |
|---|---|
| From–To の全抽出 | 今期に解く必要のある Critical / High の要約 |
| 「後で詳細を読める状態」がゴール | 課題認識・方針・次アクションの合意がゴール |
| マップから入る | 目指す姿・推進体制・今期施策を前提にしてからマップへ |
| 統合スケジュール案まで一気に出す | ①現行整理 ②課題を載せる、まで。③更新案は後 |

優先度は、プログラム目標への影響 × 主要マイルストン／クリティカルパス、で Critical / High を切る。中間報告では、さらに **今期施策の達成に効くもの** で確認対象を絞る。通常の PJ 内課題管理で足りる行は、確認の主線に載せない。

スケジュールは、現行計画の上に間の課題を載せて可視化する。更新案は、確認が取れてから作る。

ロードマップ策定の場に現場を広く入れると、策定期限に間に合わないことがある。そのときは、期限を黙って守るために巻き込みを削らない。速度・具体性・納得のトレードオフをオプションとして出す。

| 型 | 向くもの | 払うもの |
|---|---|---|
| 短期・トップダウン | 方針の確定が先 | 現場具体性は限定的 |
| ハイブリッド | 上位の方向付け＋重点テーマだけ共同検討 | テーマを絞る必要がある |
| 現場協働 | 実態を反映した詳細 | 期間と並行リソースが要る |

ワークショップはテーマごとに呼び分ける。名簿を先に厚くしない（`knowledge/patterns/activation-first-for-site-led-work.md`）。策定の場と定着の場は混ぜない（`knowledge/patterns/formulation-comms-vs-adoption-comms.md`）。

## Signals

- 中間報告が、抽出表の全件ウォークになっている  
- 関係図・課題表の前に、目指す姿と今期施策の共有前提が無い  
- 「詳細は会後に読んでください」が、その場のゴールになっている  
- 統合スケジュールの更新案を、現行と課題載せより先に出している  
- 巻き込みを厚くすると期限に届かないのに、オプションを出さず日程だけ守ろうとしている  
- Critical / High の定義はあるが、今日確認する集合が切られていない  

## Core rule

> Interim confirms a filtered set against shared premises. The working extraction stays working paper. Do not trade involvement for the calendar in silence; name the options.
