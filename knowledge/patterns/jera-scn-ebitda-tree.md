## 1. なぜ EBIDTA ツリーを SCN の背骨にするか

### 1.1 課題（従来 SCN の弱点）

| 弱点 | 具体 |
|------|------|
| 施策との接続が弱い | Enabler 層に Technology が並び、**誰のどんな行動→EBITDA** が見えない |
| 会話のフレームが分裂 | 森崎様・McK は EBITDA/Value Driver、長嶋様報告は SCN/KOPT、現場は KPI/アプリ |
| DPP 再演リスク | ツールマッピングで終わり、利用率 KPI 化（G7） |

### 1.2 McKinsey 6/29 の合意（SCN 再設計の入力）

- EBITDA 分解は**分析ではなく**「ツール→仕事のやり方→判断・行動→成果」の**一連の流れ**として設計する（6/29 メモ p.1）
- **発電所長＝EBITDA 成果責任主体**。DX/デジタルは手段（1C）
- **デジタル＋非デジタルの包括目標**を EBITDA ツリー 1 本に載せる（1B）
- モデル発電所は **1 拠点×1–2 プロセス×2–3 年ストレッチ目標**（2B, 3A）
- DPP 失敗＝横展開前成果確認不足・業務統制未連携・アプリ先行（2B）— **BPR として横展開可能に設計**

### 1.3 SCN への当てはめ方

| SCN 層 | EBITDA ツリー基準での役割 |
|--------|---------------------------|
| **Value** | 頂点＝**発電 EBITDA 最大化**（Outcome KPI）。DX/AI は Value に置かない |
| **Capability** | **EBITDA ツリーの枝＝「～できる能力」** に展開。Monitor KPI は McK 先行/遅行指標 |
| **Enabler (KOPT)** | プログラム束（AMP / DGD / Team DX / 自立経営）＋重点施策。Technology は手段列 |
| **主体列（拡張）** | 各ノードに **所長裁量 / 本社主管 / DX手段** を付与し、報告・施策マッピングを同一フレームで行う |

**長嶋様→森崎様報告での使い方:** 施策進捗は Enabler、現場変化は Capability Monitor KPI、経営インパクトは Value（EBITDA 枝）に **同じツリー上で昇格** して説明する。

### 1.4 有報整合の設計原則（2026-08-13 レビュー反映）

有価証券報告書（第10期・2025年3月期、`securities_report2506.pdf`）との突合レビューに基づき、**Value と費用枝の会計基準・範囲を統一**する。

| 設計判断 | 内容 |
|---------|------|
| **採用基準** | **個別財務諸表（JGAAP・親会社単体）** に統一 |
| **Value-1** | **電気事業営業利益 124,483 百万円**（有報 P.140–142 個別・電気事業） |
| **非採用** | 連結 IFRS セグメント利益 124,324 百万円（P.85）— 費用枝（個別）と縦足しが成立しないため |
| **EBITDA 加算 D&A** | **116,753 百万円**（個別・汽力発電費内減価償却費）。連結セグメント D&A 199,593 百万円（P.85）とは別物 |
| **スコープ** | **電気事業（汽力発電費）のみ**。ガス供給事業（収益 421,320／費用 415,958 百万円）は本ツリー対象外 |
| **網羅性** | 主要変動費・固定費の**抜粋**。一般管理費・接続供給託送料・事業税（計 185,496 百万円）は未掲載 |
| **出典ページ** | 有報**フッター印字**ページ番号（P.140–142、P.85）を使用。PDF 内部ページ順とは異なる |

**符号ルール:** 収益項目（＋）と費用項目（－）をツリー上で明示。Cap-A には収益（他社販売電力料等）と費用（他社購入電力料）が混在するため、P/L 種別を区別する。

**Capability 紐づけ:** 燃料費・人件費等は**複数 Capability に重複紐づけ**可（1 費目→複数能力の設計意図）。排他分割ではない。

**担当者名:** 手川 PM はヒアリング資料で確認済。AMP PJ オーナー（旧表記「高橋 PJ」）は体制図で要最新確認。

## 2. EBITDA ツリー構造（McK 6/29 p.7 ベース）

```
発電EBITDA（円）                          ← SCN Value-1（Outcome）
└─ 粗利益
    ├─ 送電電力量（MWh）                  ← 収益ドライバー Cap-A
    │     × スプレッド（円/MWh）
    ├─ O&M 固定費（円）                   ← コストドライバー Cap-B
    │     ├─ メンテナンス費
    │     │     └─ 単価 × 数量
    │     ├─ オペレーション費
    │     │     └─ 可変費・起動費・効率
    │     └─ 内部/外部コスト
    ├─ 計画停止（MWh）                    ← Cap-C1（McK 3A-①）
    └─ 計画外停止（MWh）                  ← Cap-C2/C3（McK 3A-②③）
```

**管理 KPI（McK p.9 例）:** アベイラビリティ、計画/計画外停止日数、熱効率、FTE、設備状態把握率、バッドアクター数 等 → **Capability Monitor**

## 8. 報告テンプレ（長嶋様→森崎様用）

同一 SCN/EBITDA フレームで 1 スライドまたは 3 行：

1. **Value:** どの EBITDA 枝に効くか（例：計画外停止 MWh → EBITDA ○○百万円相当）
2. **Capability:** 所長/本社のどの能力が変わったか（Monitor KPI の Before/After）
3. **Enabler:** どのプログラム（AMP/DGD/PoC）のどの施策か—**利用率ではなく成果連鎖**
