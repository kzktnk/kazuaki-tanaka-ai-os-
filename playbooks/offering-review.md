# Offering review (transformation)

文章校正ではなく、**売れるオファリングとして成立しているか**を順に見る。良さの定義は `standards/consulting-review.md`。

## Trigger

変革推進・PMO・Change・大規模 DX のオファリング資料、カタログ、提案転用前。

## Principle

因果が一読できること。

```text
Client Pain → Why Change → To-Be → Transformation Mechanism
        → Offering / Services → Adoption & Execution
        → Business Outcomes → Why Us
```

混ぜない:

- **To-Be** — 実現したい状態  
- **Mechanism** — 変革を起こし継続させる仕組み  
- **Offering** — その仕組みを設計・実装・運営するサービス  
- **Program Management** — 施策の統合・統制  
- **Change Management** — 人・組織の行動変容  

Description / Value / Outcomes が同じ文の繰り返しなら構造が無い。

## Sequence

1. 30秒で「誰の、どの問題を、何で解くサービスか」言えるか。言えないなら詳細に入らない。  
2. 用語の階層（To-Be / Mechanism / PMO / CM / Value Realization）。  
3. Pain はプロジェクト管理の困りごとだけにしない（可視性、ガバナンス、定着、リーダーシップ、効果実現）。  
4. Value Proposition は What の再掲ではない。課題 × アプローチ × 成果。  
5. 顧客が「何を買うか」がモジュールで見えるか。  
6. CM と PMO の主軸が分かるか。両方書くなら役割が違うこと。  
7. 成果とサービスに因果があるか。「一体提供する」は理由ではない。  

## Stop

- Scope が特定できない  
- PMO と CM のどちらが主軸か分からない  
- To-Be と手段が同じ言葉  

## Outputs

- 1文のオファリング定義  
- 用語の修正指示  
- 買うもののモジュール一覧  
- 構造修正か表現修正かの切り分け
