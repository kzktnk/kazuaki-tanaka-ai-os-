# Public Multi-Lot Construction PMO Playbook

**Version:** v0.1  
**Status:** Active  
**Owner:** Kazuaki Tanaka  
**Purpose:** 共同利用基盤など、**複数の構築ロットが同時に試験・移行する**ときの官側工程管理を、進捗会議の書記ではなく **次工程の開始判定** として回す  
**Use when:** 運用者が複数請負を抱え、結合／総合／運用試験、移行リハ、受入、本番が輻輳する。品質は計画確認と結果確認が分かれていない  
**Do not use as-is for:** 調達方式・総合評価の設計（`frameworks/public-it-procurement-support.md`）、改革PMOの立ち上げ（`playbooks/pmo-function-standup.md`）、売手の Delivery Lead（`frameworks/delivery-leadership.md`）

Pairs with `domains/public-defense.md`（共同利用の第三アクター）and `knowledge/patterns/shared-operator-vs-ministry-vs-municipality.md`. 買手／売手の境界は作業前に切る。

## Trigger

契約後の官側PMOが、各社の進捗資料を集約している。試験環境が足りない、手順書がロットごとに閉じている、経営層への説明と作業PMOが同じスライドである、次工程の開始が「大過なし」で決まる。

## Objective

運用者が、**証拠付きで次工程を始めてよいか**を決められる。ロット横断の依存、文書統合、保全、対外説明の残リスクが見える。請負の作業を代行しない。

## Prerequisites

- 役割が官側PMOである（応札用の評価対応表を、品質ゲートに使わない）  
- ロットの一覧と契約境界がある（中身の系統図は原本。リポジトリにコピーしない）  
- 開始判定のオーナーが運用者側にある  

## Required inputs

- マスタスケジュール（輻輳する試験・移行の重なりが見えるもの）  
- 各ロットの計画類（試験、移行、運用準備）と、計画レビューの観点  
- 課題・変更・リスクの台帳の型（実データは原本）  
機密の団体名、円、機器数、手順本文、提案本文は原本のみ。

## Escalation conditions

- ロットが各自「完了」でも、運用者が一つの受入物語を書けない → スポンサーへ切替不可を上げる  
- 手順書・操作書がベンダー単位のままサービスイン日前 → 文書マージをクリティカルパスにする  
- 開始判定が会議日程だけ決まっている → 報告フォーマット（残タスク、証拠、条件付きGo）を先に固定する  
- 試験環境が輻輳しているのに環境管理がロット任せ → 官側の環境ルールを先に置く  

## Sequence

1. **アクターとロットを固定する**  
   省／運用者／団体を混ぜない。コア、施設・拠点、チャネルなど、同時進行の塊を名前ではなく **依存** で書く。

2. **PMOが見るものと請負がやるものを分ける**  
   進捗・課題・変更・品質・保全・関連案件・対外調整は見る。設計・試験実施・移行操作は請負。受入試験は運用者の作業であり、支援は構造化まで。

3. **工程ごとに「計画確認 → 結果確認」を置く**  
   結合、総合、運用試験、移行リハは、計画の妥当と結果の十分を別ゲートにする。計画レビューの観点を先に配り、結果表だけ後追いしない。

4. **開始判定のカレンダーと書式を先に出す**  
   次工程名、残タスク、条件付きGo、参考証拠。事業者報告と運用者判定を分ける。判定会議は意思決定であり、進捗の読み合わせではない。

5. **輻輳する試験環境を一つの管理対象にする**  
   同時試験を前提に、環境の割り当てと変更をテーラリングする。実案件の環境表は原本。

6. **運用準備を文書マージとして扱う**  
   運用手順と操作手順が複数ソースなら、完成形の目次と差分管理が成果である。構成・変更管理の台帳は設計納品と本番後プロセスを繋ぐ。手順本文は登録しない。

7. **経営層と作業PMOの高度を分ける**  
   執行部は残リスクと判断依頼。詳細WBSは作業層。同じデッキを使い回さない。

8. **本番移行は支援であり実施ではない**  
   切替の条件、リハ結果、残件の扱いを構造化する。操作の代行は範囲外。

## Done when

- 次工程の開始判定が、残タスクと証拠で記録されている  
- 品質が計画確認と結果確認に分かれている  
- 運用文書のマージ方針が、サービスイン前のパスになっている  
- ロット完了と運用者の受入が、同じ文で宣言されていない  

## Limitations

単一請負のWBS詳細、法定の調達設計、仕様本文、系統図、試験実数、手順書の中身は対象外。民間ERPのPMO立ち上げとも対象が違う。
