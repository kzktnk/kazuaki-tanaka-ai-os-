# Document Management Standard

**Version:** v1.0  
**Status:** Active  
**Owner:** Kazuaki Tanaka  
**Origin:** 大規模基幹系更改案件のドキュメント標準（2003/12）を一般化。クライアント名・固有情報・実様式なし。

---

## Purpose

システム開発・維持運用で作成する文書について、**番号・承認・台帳・配布・改訂**を一貫して管理し、関係者が**最新版**を利用できるようにする標準です。

`standards/development-standards-framework.md` が開発標準全体の構成を定義するのに対し、本書は**文書そのものの管理と作成基準**に特化します。

---

## When to Use

- 開発標準セットにドキュメント管理規約を含めるとき
- 設計書・試験計画・運用引継資料の**表紙・改定履歴・承認フロー**を定義するとき
- 発注側とベンダー間の**文書受渡し**ルールを合意するとき
- `requirements-document-outline.md` の要件定義書を**下流設計文書**へ接続するとき

---

## Scope

### 目的（一般化）

マネージメントシステムを維持するため、必要な手順・基準を**所定の責任者の承認**を得て文書化し、必要な関係者が最新版を参照できる状態を保つ。

### 適用対象

発注側と開発側がやり取りし、**発注側の承認が必要な文書**に適用する。

### 文書の4分類

| 分類 | 説明 | 例 |
|------|------|-----|
| **（1）記録類** | 履歴として残す。文書番号管理の対象外 | 議事録、進捗管理表、進捗報告書、問題管理表、設計連絡票、仕様確認依頼書、レビュー結果、試験結果報告 |
| **（2）開発関連文書類** | 成果物として版管理する設計・計画文書 | 要件定義書、方式概要/詳細/方式設計書、総合試験計画、移行設計、運用設計、運用引継説明 |
| **（3）標準類** | 特定プロジェクトに限定されない標準・規約 | 開発標準、ガイドライン、規約 |
| **（4）様式類** | 標準またはプロジェクトで定義したテンプレート | 各種様式（表紙、台帳、申請書等） |

**管理手順の対象:** 開発関連文書類、標準類、様式類。**記録類**は別フロー（ファイル名等で区別）。

| 1 | 開発関連文書類 | **要定** | 要件定義書 |
| 2 | | **方概** | 方式概要設計書 |
| 3 | | **詳設** | 詳細設計書 |
| 4 | | **方設** | 方式設計書 |
| 5 | | **総計** | 総合試験計画書 |

## Document Numbering (Generalized Pattern)

クライアント固有の ID（システムID・業務ID）は案件ごとに定義する。リポジトリには**パターンのみ**記載する。

### 記録類

- 文書番号管理は行わない
- ファイル名をフッタ等に印刷し区別可能にする

### 開発関連文書類

```
{システムID}{業務ID}-{文書区分}[-{特例番号}]
```

### 標準類

```
{システムID}{業務ID}-{文書区分}-{識別番号}[-{特例番号}]
```

- **識別番号:** 半角4文字（上2: 英数字＝文書単位、下2: 数字＝文書内連番）

### 様式類

```
{システムID}{業務ID}-{文書区分}-{様式番号}[-{特例番号}]
```

### 特例番号

- 半角2文字
- 文書が大きすぎる、同一様式で印刷方向が異なる等、番号の一意性が必要な場合に付与

**注意:** 上記は2003年当時の体系。クラウド/Git 管理では `{プロジェクト}-{文書区分}-{連番}` 等に置き換えてよいが、**区分略称と台帳**は維持すること。

## Roles

| 役割 | 責任 |
|------|------|
| **文書作成者** | 本文作成、表紙・台帳への登録、番号取得 |
| **文書作成責任者** | 内容査閲、表紙の作成責任者欄署名、差し戻し対応 |
| **文書承認者** | 発注側承認。位置づけ・内容・上位/関連文書整合・制定/改定日を確認 |
| **文書管理担当者** | 台帳・配布・旧版回収・保管・廃棄。プロジェクトリーダーが指名 |
| **文書受領担当者 / 利用者** | 受領登録、保管、旧版破棄または「旧版」表記、返却 |

承認は**捺印不要**とし、承認記録が残る方法（電子承認、表紙欄、ワークフロー等）で代行する。

## Document Control Workflow

### 新規制定・改訂の発動

文書作成責任者が以下のいずれかで改訂を起票する：

1. 組織・体制・業務変更により必要になったとき  
2. 是正・予防処置の一環として必要になったとき  
3. マネージメントシステム全体の見直しが必要になったとき  
4. 文書の大規模見直し・修正があるとき  

### フロー概要

```
作成 → 作成責任者査閲 → 承認 → 台帳登録 → 配布（必要時）→ 受領・保管
                ↑ 差し戻し                    ↓
                                    旧版回収・廃棄・関連部門連絡
```

### 新規制定時の表紙必須項目（様式除く）

| 項目 | 内容 |
|------|------|
| 文書標題 | 文書名 |
| 文書番号 | 台帳から取得 |
| 制定年月日 | |
| 改定年月日 | 初版は空可 |
| 版数 | 例: 1.0 |
| 作成者 | |
| 作成責任者 | |
| 文書承認者 | |

**用紙:** 原則 A4 縦。図面・横長表は例外可。

### 承認時の確認事項

1. 文書の位置づけの適切性  
2. 内容の妥当性  
3. 上位文書および関連文書との整合性  
4. 新規制定日（改定日）  

### 台帳管理

- **文書履歴管理台帳**をシステム（またはプログラム）単位で維持
- 番号・改訂日を台帳で管理。電子台帳の場合は更新時バックアップ必須
- **文書配布管理台帳**は極秘文書の配布・回収に使用

### 配布

- 承認済み原本（または正本）をコピーし、配布台帳に基づき配布。電子配布可
- 受領者は台帳に記録。旧版回収が必要な場合は期限內に返却
- 回収した旧版は「旧版」と表記し、最新版と分離保管。保管期限後に廃棄または期限再設定

### 関連部門への連絡

文書管理担当者は、名称・版数・制定日・**効力発生日**、および**無効・廃棄となる旧文書**を関係グループに連絡する。

## Confidentiality Levels

| レベル | 開示範囲 | 配布管理 |
|--------|---------|---------|
| **プロジェクト外秘** | 当該システムのプロジェクトメンバー | オープン範囲内は配布管理不要。社外公開は発注側許可必須 |
| **業務グループ外秘** | 当該業務担当メンバー | 同上 |
| **極秘** | 指定メンバーのみ | **配布管理（貸出・回収）必須**。都度、極秘文書の管理担当を任命 |

---

## Retention and Disposal

- 保管期限はシステム／プログラムで取り決め
- 廃棄されない限り、**最新版**はシステム存続期間、所定場所に保管
- 旧版は最新版と別保管し、誤用防止。期限経過後、不要分は廃棄
- 標準類・様式類は**年1回**見直し（直近3ヶ月以内の新規/改訂は除外可）。改訂要否を承認者へ報告

## Document Structure (Creation Standard)

設計書等、維持管理が必要な文書の**推奨構成**：

1. 表紙  
2. 改定履歴  
3. 目次  
4. 文書本体  

### Typography (参考 — 案件で更新可)

| 要素 | 推奨 |
|------|------|
| 編・章タイトル | 18pt ボールド |
| 見出し1–2 | 12pt ボールド |
| 見出し3–4 | 10pt ボールド |
| 本文 | 10pt |
| 表・図・画面/帳票内 | 規定しない（可読性優先） |

フォントはプロジェクト標準（例: ゴシック系）を1つに統一。

### Heading Numbering (参考)

| レベル | 形式 | 例 |
|--------|------|-----|
| 編 | 第N編（全角） | 第１編 |
| 章 | 第N章 | 第１章 |
| 見出し1 | １　タイトル | １　概要 |
| 見出し2 | １．１　タイトル | １．１ 目的 |
| 見出し3 | １．１．１　タイトル | |
| 見出し4 | １．１．１．１　タイトル | |
| 大連番 | （１） | |
| 中連番 | ① ② | |
| 小連番 | ア. イ. | |
| 小小連番 | a. b.（半角） | |

見出し番号とタイトルの間は**全角空白1字**。

### Figures and Tables

- **表:** 名称は表の**上**・中央。形式 `表{章}-{連番}　{名称}`（例: 表１．１－３　比較表）
- **図:** 同様に `図{章}-{連番}　{名称}`

## Writing Principles

1. **最新版の一意性** — 流通するのは承認済み最新版のみ（極秘は回収まで厳格に）  
2. **トレーサビリティ** — 改定履歴と台帳で「いつ・誰が・何を」変更したか残す  
3. **整合性** — 上位文書（要定→方概→詳設）の矛盾を承認前に解消  
4. **記録と成果物の分離** — 議事録・進捗表は記録類として軽量管理、設計書は版管理  
5. **一般化** — リポジトリ用コピーからクライアント固有ID・実様式・個人名を除去  

`core/author-voice.md` の留保（案、Rev）と整合させ、初版から確定口調にしない。
