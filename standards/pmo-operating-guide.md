## Purpose

Operational standard for **designing, standing up, and running** a transformation PMO or assessing PMO effectiveness in an engagement.

---

## When to Stand Up PMO

Use PMO when **two or more** of these conditions apply:

- Projects proliferate without priority or portfolio view
- Expected benefits and risks are not measured at program level
- Vision/strategy linkage to individual projects is unclear
- PM authority, skills, or budget are inadequate
- Cross-project information is unavailable in real time
- Stakeholder commitment is weak
- Culture or HR systems undervalue project contribution
- Line–project–executive **management gap** causes delays and rework

## pmo vs PMO Decision

| Question | If yes → |
|----------|----------|
| Single or loosely related projects? | PO / PSO / pmo |
| Strategic transformation with many interdependent projects? | **PMO** |
| Need portfolio prioritization and benefit aggregation? | **PMO** |
| Need enterprise change leadership? | **PMO** |

## PMO Mission and Role

| | pmo | PMO |
|---|-----|-----|
| **Mission** | Project success | Enterprise strategy realization |
| **Role** | Project Management (multi) | Program Management |
| **Change scope** | Project stakeholders | Enterprise stakeholders |

## Function Map

### Three Function Groups

| Group | Intent |
|-------|--------|
| **Support** | Enable teams to deliver |
| **Management & integration** | Run multi-project operating rhythm |
| **Strategic alignment & competency** | Connect to strategy; build enduring capability |

### PMO Function Domains

| Domain | Typical responsibilities |
|--------|-------------------------|
| **Portfolio Management** | Program strategy mgmt; monitoring & reporting; benefit management; strategic alignment |
| **Human Capital Management** | Competency mgmt; project resource mgmt; long-term resource mgmt; learning mgmt |
| **Knowledge Management** | PM process standards; PMIS mgmt; project knowledge sharing |
| **Change Management** | Stakeholder mgmt; communication; org alignment; program risk/issue (change control) |
| **Integration Management** | Cross-project coordination; schedule/resource visibility |
| **Schedule / Resource Management** | Multi-project planning and capacity (often under pmo + PMO) |

### pmo vs PMO on Change

- **pmo:** Change Management (project stakeholder)
- **PMO:** Change Management (enterprise stakeholder)

## Program Planning (Point of View)

Before PMO implementation, clarify:

```
Current Business Model → Future Business Model
         ↑                        ↑
    Big Issues /           Programs & projects
    Management challenges   to close the gap
         ↑
Vision & Strategy
```

Dimensions to assess: customer, product, process, IT/technology, organization/people, alliance, core competencies.

**Program planning loop:**

1. Recognize need for new/ changed projects
2. Align with strategy
3. Analyze portfolio (add / stop / defer)
4. Program scenario and benefit/risk analysis
5. Project charter and planning
6. Continuous portfolio refresh

## PMO Implementation Components

When implementing PMO, establish:

| Component | Content |
|-----------|---------|
| **Organization design** | PMO structure, roles, interfaces to line and executives |
| **Program management process** | Visioning → Planning → Implementation → Improvement |
| **Project management standardization** | Methods, templates, quality bars |
| **Transformation governance** | Steering, decision rights, escalation |
| **PMIS** | Portfolio visibility, dashboards, change control workflow |

### PMO Lifecycle

PMO staffing often **peaks during transformation waves** and may become **more permanent** as program maturity increases (Transformations A→E pattern in source materials).

## PPM Process Highlights

### Initiation / Planning (program + project)

Key decision points:

- New/add project request → strategic alignment check
- Portfolio analysis → approve / defer / stop
- Program scenario, benefit plan, risk plan, stakeholder plan
- Project charter, WBS, schedule, cost, quality, communication, risk, procurement plans
- Program plan approval; portfolio update; dashboard registration

### Execution / Control

Key operating rhythm:

- Project progress reporting → program performance analysis
- Change request → impact analysis → program review → approval
- Multi-project monitoring; benefit continuous measurement
- Program progress meetings; program reports
- Knowledge sharing; team development; stakeholder management
- Project stop/defer when portfolio rebalancing requires

**PMO role in control:** Own program-level change control, benefit tracking, and cross-project impact assessment — not only collecting status slides.

---

## Program Status and Visibility

Principles:

- **Project level:** WBS, schedule, resource, cost plans are foundational
- **Multi-project level:** Aggregate schedule, resource, cost for early problem detection
- **Program level:** Portfolio, benefits, risks, stakeholder commitment on one dashboard narrative

Tool choice is engagement-specific; the standard requires **visibility**, not a named product.

## Change Management Operating Standard

### Why it matters

- Middle management and line supervisors are primary resistance sources in improvement programs
- M&A and BPR failures often trace to **people**, not financial logic

### Emotional curve to manage

```
Productivity dip: confusion → discouragement → quick wins → proficiency → smooth adoption
```

Interventions: communication, quick wins, role clarity, support channels, ownership building.

### Stakeholder maturity model

| Stage | State | PMO action |
|-------|-------|------------|
| Unawareness | No interest | Awareness campaigns |
| Awareness | Understands need | Build interest |
| Buy-in | Will cooperate | Engage in design |
| Ownership | Committed to success | Delegate and celebrate |

## PMO Design Checklist

Before go-live:

- [ ] Mission defined (pmo vs PMO scope explicit)
- [ ] Management gap addressed (exec / line / project interfaces)
- [ ] Portfolio criteria and stop/start rules agreed
- [ ] Program process aligned to 4 phases
- [ ] Benefit and risk measurement at program level
- [ ] Change management resourced (enterprise + project)
- [ ] PM standards and PMIS minimum viable visibility
- [ ] Steering cadence and escalation paths documented

---

## Anti-Patterns

| Anti-pattern | Fix |
|--------------|-----|
| PMO = report collation only | Add portfolio, benefit, change ownership |
| Every project “top priority” | Portfolio governance and explicit trade-offs |
| PMO disconnected from strategy | Strategic alignment step in every intake |
| Permanent firefighting, no stop option | Stop/defer project requests in portfolio process |
| Tool rollout without process | PPM process before PMIS customization |
| Change management after go-live | Stakeholder plan at program planning phase |
