---

## Purpose

方式選定（Phase 410）**後**に作成する要件定義書の**標準章立て**です。

機能要件だけでなく、非機能・移行・運用・テストまで含む**エンタープライズ向け完全版**の骨格です。  
案件に応じて章の追加・統合は可。ただし**方式FIX前に本書を書き始めない**。

---

## When to Use

- Phase 420 要件定義書の作成・レビュー
- RFP Appendix の要件整理
- 設計・調達フェーズへの引継ぎ

## Appendices（別添・参照）

要件定義書本体と分離してよい典型別添：

| 別添 | 内容 | 元アーキタイプ |
|------|------|--------------|
| SLA | サービスレベル定義 | 運用・可用性 |
| 業務プロセスマップ | As-Is / To-Be BPM | 業務改革 |
| 業務記述書 | 機能要件の詳細 | 業務領域 |
| 内部/外部連携ポイント | インターフェース一覧 | 連携設計 |
| 帳票一覧 | 出力帳票 | 業務 |
| 管理業務一覧 | 運用業務 | 運用 |
| 分析項目一覧 | レポート・KPI | 分析 |
| 現行基盤概要 | As-Is技術 | 200調査 |
| 開発標準 | 開発・品質基準 | 調達 |

**原則:** 本体は**要件**、別添は**詳細・一覧**。本体から参照番号でリンク。

## Writing Principles

1. **方式と整合** — 410で選んだ方式と矛盾する要件を書かない
2. **テスト可能** — 「適切に」より指標・条件
3. **スコープ境界** — 対象外を明示
4. **用語統一** — クライアント/プロジェクト用語集に合わせる
5. **段階的FIX** — 案→レビュー→Rev更新。初版から確定口調にしない

`core/author-voice.md` の留保（案、想定）と整合。
