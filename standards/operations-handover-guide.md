**Version:** v1.0  
**Status:** Active  
**Owner:** Kazuaki Tanaka  
**Origin:** 大規模基幹系更改案件の運用引継ガイドライン（2003/12）を一般化。クライアント名・ベンダー名・固有情報なし。

---

## Purpose

開発体制から運用体制へ移行する際の**引継体制・資料・手順・完了基準**を定義する標準です。

実現目標:

1. 開発から運用への**円滑な移管**  
2. **早期安定運用**  
3. 現行運用体制に合わせた運用による**コスト削減**  

---

## When to Use

- 総合試験〜総合運転試験〜Go-live 前の引継計画
- 運用引継説明書（運説）の作成・レビュー
- 開発ベンダー / AP維持管理 / 運用委託の**責任分界**合意
- RFP・契約の運用引継条項の具体化

---

## Organization Models

### 新規開発（典型）

| 体制 | 担当 |
|------|------|
| **開発体制** | 開発ベンダー |
| **運用体制** | AP維持管理 + 運用委託 |

### 維持開発（典型）

| 体制 | 担当 |
|------|------|
| **開発体制** | AP維持管理 |
| **運用体制** | 運用委託 |

### 引継対象

- **業務 AP** と **本番環境** が開発体制 → 運用体制へ移管
- 開発/試験環境は本番との差分がある場合、必要に応じて限定引継

---

## Roles

| 関係者 | 役割 |
|--------|------|
| **発注側** | 4社調整、引継計画/資料の指示・確認、完了判定 |
| **開発ベンダー** | 引継計画・引継資料作成、運用委託/AP維持への説明 |
| **AP維持管理** | 業務 AP の維持管理引受。維持開発時は引継計画作成も |
| **運用委託** | 環境維持、ジョブスケジュール変更等の運用引受 |

**前提:** AP維持管理は AP 基礎知識、運用委託は環境基礎知識を有すること。

---

## Handover Flow

```
① 体制確立
  → ② 引継計画・資料の作成指示（総合試験頃）
  → ③ 計画・資料の確認（総合運転試験）
  → ④ 引継説明の実施
  → ⑤ 完了確認（残項目なし・完了報告）
```

**原則:** サービス開始前に引継完了。

### 二系統の引継

| 系統 | 内容 | 実施者 → 受け手 |
|------|------|----------------|
| **AP保守引継** | 業務 AP、詳設、バッチ/メッセージ仕様 | 開発ベンダー → AP維持管理 |
| **運用引継** | 環境定義、運用設計、ジョブ/運用操作 | 開発ベンダー/AP維持 → 運用委託 |

## Handover Plan Contents

引継計画に含める項目：

| 項目 | 内容 |
|------|------|
| 引継完了目標日 | Go-live 前の完了日 |
| 引継対象 | 資料・環境・業務の範囲 |
| 説明スケジュール | 説明会日程 |
| 問合せルール | 回数、窓口、応答 SLA |

## Handover Documents

| 資料 | 作成時期 | 用途 |
|------|---------|------|
| 詳細設計書（詳設） | 設計工程 | バッチ・メッセージ等の業務仕様 |
| 方式設計書（方設） | 設計工程 | 環境定義（HW/OS/MW/DB/ラック等） |
| 運用設計書（運設） | 設計工程 | 業務運用に必要な仕様 |
| **運用引継説明書（運説）** | 総合試験工程 | 上記を参考に引継説明用に作成 |

引継後、AP維持管理・運用委託は実運用に即した詳細資料へ展開してよい。

### 最小記載内容（運用委託向け）

| 資料 | 引継項目 | 最小内容 |
|------|---------|---------|
| 詳設 | バッチ・メッセージ | ジョブスケジュール構成、ログメッセージ |
| 方設 | 環境定義 | HW/OS/MW/DB、ラック・電源 |
| 運設 | 運用設計 | 業務運用に必要な仕様 |
| 運説 | 運用手順 | 起停、障害対応、日常操作 |

---

## Handover Criteria

| 基準 | 内容 |
|------|------|
| 資料 | 引継資料に**不備がない** |
| 品質 | 引継内容が妥当で、**問題なく説明できる**品質が確保されている |
| 合意 | 関係各社でスケジュール・内容が合意されている |
| 完了 | 残項目なし、完了報告受領 |

---

## Client Checkpoints

| 手順 | チェック |
|------|---------|
| 体制確立 | AP維持管理に維持作業の基礎知識があるか |
| 計画・資料 | スケジュール合意、開始/終了日明確、資料不備なし、内容妥当 |
| 引継説明 | 説明が確実に実施されたか |
| 完了確認 | 残項目なし、完了報告あり |
