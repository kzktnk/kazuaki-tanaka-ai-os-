## Purpose

Operational standard for **running strategy consulting engagements** — problem scoping, logic trees, analysis planning, data gathering, scenario work, and solution evaluation. Use as a checklist when starting or reviewing strategy work.

---

## When to Use

| Situation | Start here |
|-----------|------------|
| New strategy / market / opportunity engagement | §Problem scoping workflow |
| Client question is vague or symptom-level | §4Cs & 1Q template |
| Team debating "what to analyze" | §Logic tree selection, §Analysis plan |
| Data collection feels unfocused | §Data gathering |
| High uncertainty industry | §Scenario envisioning |
| Multiple options on the table | §Decision criteria and option matrix |
| Final recommendation pack | §Storyboard and communication |

## Problem Scoping Workflow

### Step 1 — Define the problem (4Cs & 1Q)

**Do not skip.** Even when the client names a process or symptom, lift to the key question.

| # | Element | Guiding questions |
|---|---------|-------------------|
| 1 | **Context** | What industry forces, competitive position, and internal gaps frame the issue? Which toolkit lens helps (business system, 3-C, 5 Forces, 7S)? |
| 2 | **Client** | Who decides to act? Coaches, sponsors, economic/technical buyers? Sensitivities, biases, prior consultant experience? Impact on their role? |
| 3 | **Criteria** | Financial metrics, strategic fit, risk tolerance, timing thresholds, success definitions? |
| 4 | **Constraints** | Excluded units/products/markets? Resource limits? Information gaps? Roles that must be preserved? |
| Q | **Question** | One clear sentence: "What must this study answer?" |

**Template (blank):**

```
Context:
Client:
Criteria:
Constraints:
Question:
```

**Quality checks:**

- [ ] Question is answerable within constraints
- [ ] Criteria reflect how the client will actually decide
- [ ] Client = decision maker, not only sponsor or project manager
- [ ] Reviewed iteratively with key stakeholders

---

### Step 2 — Structure the problem (logic tree)

**Goal:** MECE decomposition from key question to analyzable issues.

**Build sequence:**

1. Agree on key question (from 4Cs & 1Q)
2. Identify the answer or decision space
3. Define starting drivers (what factors underlie the issue?)
4. Identify all plausible branches
5. Review logic flow and ordering
6. Share with team; refine

**Tree selection matrix:**

| If… | Start with |
|-----|------------|
| Exploring full option space early | Deductive tree |
| Testing one recommended path | Hypothesis tree |
| Choosing among strategic alternatives | Issue map (yes/no) |
| Low domain familiarity | Deductive, then narrow |
| High familiarity, one alternative | Hypothesis tree |

**MECE tests:**

- [ ] Mutually exclusive — no double-counting
- [ ] Collectively exhaustive — no obvious gaps
- [ ] Endpoints phrased as questions (hypothesis/deductive) or yes/no decisions (issue map)
- [ ] Each branch traceable to key question

**Common frameworks for MECE splits:** Revenue/cost/investment; internal/external; company/customer/competitor; suitability/feasibility/acceptability.

---

### Step 3 — Plan the approach

**Analysis plan columns:**

| Column | Definition |
|--------|------------|
| **Issue** | Important unresolved question; often yes/no phrasing |
| **Hypothesis** | Likely resolution and rationale |
| **Analysis** | Models/analyses to test hypothesis |
| **Information source** | Where data comes from |
| **End product** | Graphic or exhibit showing the "so what" |

**Derived artifacts (in order):**

1. **Analysis plan** — consensus on what proves/disproves each issue
2. **Storyboard** — storyline chapters (each readable standalone)
3. **Work plan** — tasks, timing, responsibility (include client vs consultant ownership)
4. **Formal agreement** — scope, deliverables, staffing, timing, contingencies

**Factors when finalizing plans:**

- Confidence level / external assurance needs
- Importance of sub-issue to overall answer
- Decision maker on this phase vs future phases
- Data availability and access
- Staff assistance and key personnel access
- Third-party reliance
- Management biases and current hypotheses
- Contingencies

**Storyboard rule:** Each storyline = one chapter of the final narrative. Draft storylines **before** deep analysis when possible.

## Data Gathering

### Process

```
Define requirements → Develop plan → Gather data → Analyze & synthesize
```

### Define data requirements

**Two purposes:**

1. **Analysis-driven** — data tied to each analysis in the plan
2. **Project-driven** — context, stakeholder management, credibility building

### Develop data gathering plan

| Element | Actions |
|---------|---------|
| **Sources** | Primary (interviews, observation) vs secondary (reports, databases) |
| **Methods** | Interviews, workshops, surveys, literature, online research, best practices |
| **Sequence** | Dependencies, logistics, deliverable timeline |
| **Responsibility** | Consultant, client, third parties |

### Interview program

**Process:** Define scope → interview guide → arrangements → conduct → summarize/analyze

**Typical sequence:**

1. Client senior management
2. Client technical / sales
3. Industry experts (PwC, government, academics)
4. Customers
5. Distributors
6. Substitutes
7. Competitors
8. Suppliers

**Interview guide principles:**

- Start from issue analysis (topics, data needs)
- Order: general → specific; external → internal; historic → current/projected
- Separate "must find out" vs "would like to know"
- Use visual aids (tables, business system diagrams)

**Format selection:**

| Nature | In-person | Phone | Focus group | Two interviewers | Client team |
|--------|-----------|-------|-------------|------------------|-------------|
| In-depth / sensitive | ✓ | | ✓ | ✓ | ✓ |
| Short / targeted | ✓ | ✓ | | | |

**Common failures:** Wrong interviewees, no guide, leading questions, no synthesis, ignoring politics.

### Workshop facilitation

Use when: alignment needed across stakeholders, scenario brainstorming, force identification, option generation.

Pre-work: clear objective, participant selection, pre-reads, facilitator + scribe roles.

## Strategy Analysis Toolkit

Use tools **in service of the key question** — not as deck filler.

### Situation assessment

| Lens | Primary tools |
|------|---------------|
| **Company (internal)** | 7S, value chain / business system, core competency, SWOT, profitability/cost, product portfolio, SVA/EVA |
| **Customer (external)** | Segmentation, market size/growth, pricing, profitability by segment, primary research, KANO/conjoint when justified |
| **Competitive (external)** | 5 Forces, value net, positioning map, benchmarking, competitor profiles, entry/exit barriers, PEST + industry analysis |

### Strategy formulation and evaluation

| Activity | Tools / methods |
|----------|-----------------|
| Create options | Deductive tree, brainstorming, scenario implications, traditional strategies (differentiation, low cost, focus, synergy, growth, preemptive move) |
| Evaluate options | Suitability (NPV, IRR, SVA, EVA, sensitivity), feasibility (capabilities, risk, implementation), acceptability (culture, stakeholders) |
| Select | Decision criteria matrix, Diamond-E fit check |

**So-what discipline:** After every exhibit, answer: *"Therefore, for our key question, this means…"*

## Scenario Envisioning Checklist

**Use when:** Industry driver impact or environmental uncertainty is moderate–high.

### Preparation

- [ ] Key question and logic tree anchor the scenario scope
- [ ] Workshop with senior client stakeholders scheduled
- [ ] Facilitator and scribe assigned

### Ten steps

- [ ] 1. Define broad future industry/market context
- [ ] 2. Brainstorm driving forces; prioritize (impact × uncertainty)
- [ ] 3. Identify boundary parameters for top forces
- [ ] 4. Hypothesize how dominant forces interact
- [ ] 5. Build 3–4 distinct scenarios within boundaries
- [ ] 6. Test scenario credibility (enabling events plausible?)
- [ ] 7. Plot evolutionary paths over time
- [ ] 8. Simulate outcomes (customer, business system, competitive reaction)
- [ ] 9. Assess client capabilities under each scenario
- [ ] 10. Develop strategy portfolio; compare to current strategy

### Scenario outputs

- Scenario narratives (name, drivers, implications)
- Implications by scenario for strategy options
- Early indicators / signposts to monitor
- Recommended strategic posture (lead, adapt, hedge)

## Solutions Identification

### Develop decision criteria first

Criteria = **minimum requirements** (needs). Exceeding criteria = benefits.

**Criteria categories:**

| Category | Examples |
|----------|----------|
| Performance | Market share, ROI, revenue/profit targets |
| Strategic fit | Vision, mission, portfolio balance |
| Competitive | Sustainable advantage, competitor response |
| Feasibility | Resources, skills, org compatibility |
| Synergy | Cross-business, HQ value-add |
| Scenario robustness | Performs across envisioned futures |

### Diamond-E fit review

For each option, assess fit across:

- External environment
- Resources
- Organization
- Management preference

Flag gaps: *Needs* without *Cans* → resource or capability gap; *Wants* without *Needs* → aspiration mismatch.

### Option evaluation matrix

| Criterion | Weight | Option A | Option B | Option C |
|-----------|--------|----------|----------|----------|
| Criterion 1 | | ✓/✗/partial | | |
| … | | | | |

**Scoring tips:**

- Weight criteria by client-stated importance (from 4Cs Criteria)
- Document trade-offs explicitly when no option wins all criteria
- Separate strategic choice from implementation sequencing

### Implementation theme prioritization

When many initiatives emerge, score themes on:

| Dimension | Indicators (examples) |
|-----------|------------------------|
| **Importance** | Prompt enterprising, secure profitability, minimize risk, universality, process priority |
| **Feasibility** | Total cost, time, resource/skills availability |

Plot on Importance × Feasibility matrix; prioritize high-importance + high-feasibility first.

## Communication and Buy-In

### Stakeholder evaluation

Before final delivery:

- [ ] Decision maker identified and briefed on criteria
- [ ] Influencers mapped (supporters, neutrals, resistors)
- [ ] Messages tailored by audience (executive vs operational)

### Delivery structure

- Lead with answer (Pyramid Principle)
- Support with logic tree branches covered in analysis
- Link recommendation to criteria agreed at project start
- Explicit next steps, owners, timing

---

## Engagement Quality Checklist

**Before analysis starts:**

- [ ] 4Cs & 1Q signed off (iteratively) with client
- [ ] Logic tree MECE and linked to key question
- [ ] Analysis plan with end products and storyboard draft
- [ ] Work plan with client/consultant responsibilities

**Mid-engagement:**

- [ ] Data gathering traceable to analysis plan
- [ ] Interim so-whats shared with client/partner
- [ ] Scope changes reflected in plan (not silent creep)

**Before recommendation:**

- [ ] Options evaluated against pre-agreed criteria
- [ ] Scenario implications addressed (if applicable)
- [ ] Implementation and risk sections proportionate to recommendation ambition
